- **一句话 takeaway**：双智能体分离可把“考试引导”与“评分判定”解耦，是在LLM对话评估中降低泄题风险的可行路径；但系统有效性仍依赖追问质量与学生/教师贡献归属的清晰界定。虚构主题与对抗性模拟学生是值得借鉴的评估安全设计。

## 3. 演员、裁判还是教师？理解长程智能体中的决策模型

- **英文标题**：Actor, Judge, or Teacher? Understanding Decision Models in Long-Horizon Agents
- **作者**：Haochen Liu、Qianhao Zhu、Zixuan Wang、Dingming Li、Tongbo Chen、Peng Qiu、Yingqi Qu、Weiming Lu、Jun Xiao、Yongliang Shen
- **分类**：cs.AI, cs.CL
- **发布时间**：2026-11-12 17:42:46 UTC
- **链接**：[原文摘要](https://arxiv.org/abs/2611.17167v1) · [PDF](https://arxiv.org/pdf/2611.17167v1)
- **匹配方向**：LLM + Agent

### 快速理解

- **研究背景**：长程智能体需要决策模型承担选择动作、评估轨迹或训练策略等不同角色，但既有工作通常把决策模型主要视为演员，并以最终行动成功率衡量其能力。尚不清楚“不会行动”的模型是否仍能通过后验评判提供有效监督。
- **核心创新**：论文把同一决策模型放入演员、裁判、教师三种角色中系统比较，提出并验证“行动差不代表教学差”的解耦观点。其核心洞察是：完整轨迹裁判能在事后看到动作后果，而演员必须在行动前预判这些后果。
- **方法概览**：作者在 ALFWorld 上评估三个决策模型和三个通用 LLM 的演员与裁判能力，并在 ALFWorld、WebShop 上检验 JEV 作为教师的效果；裁判提示包含整条轨迹，并对比“该动作是否有帮助”与“任务是否会成功”两类提问。教师实验中，他们用 JEV 为 Qwen2.5-1.5B 策略提供奖励/打分，并结合 GRPO 训练。
- **结果与结论**：作为演员，六个模型都被更容易出现的子目标吸引，偏离必须先完成的前置子目标；作为完整轨迹裁判，它们能认可朝向前置子目标的步骤，且“动作是否有帮助”的提问更能分离有用与无用动作。JEV 作教师将 GRPO 训练的 Qwen2.5-1.5B 成功率从 72.8% 提升至 82.9%（ALFWorld）、56.8% 至 71.4%（WebShop）。
- **一句话 takeaway**：长程智能体不应只用行动成功率判断决策模型价值：行动失败可能源于事前难以预判后果，而事后完整轨迹评判能补足这一信息。实践上可让弱演员搭配强裁判/教师，用“是否帮助”的细粒度评判改进策略学习。

**中文摘要**：决策模型以类型化输出回答问题，例如在一组选项中给出每个选项的概率，因此同一个模型既可以选择智能体的动作、评估已经执行的动作，也可以通过给每个动作打分来用强化学习训练策略。以往研究主要把决策模型当作“演员”，并用其行动表现来评价价值。本文追问：一个表现差的演员是否仍可能成为好教师。研究在 ALFWorld 上比较三个决策模型与三个通用大模型作为演员和裁判的表现，并在 ALFWorld 与 WebShop 上使用 JEV 作为教师。结果显示，作为演员时，六个模型都会被更容易的子目标带偏，偏离必须先完成的子目标；但作为能看到完整轨迹的裁判，同一批模型会认可通往该子目标的步骤，并且询问“每个动作是否有帮助”比询问“任务是否会成功”更能区分有用与无用动作。作为教师，JEV 将基于 GRPO 训练的 Qwen2.5-1.5B 策略在 ALFWorld 上成功率从 72.8% 提升到 82.9%，在 WebShop 上从 56.8% 提升到 71.4%。这些结果说明，差的演员仍可能教得好，因为回合结束后再判断动作能够揭示行动时必须预判的后果。代码见 https://github.com/ZJU-REAL/decision-agents。

## 5. CapLite：无需模型编写安全工件的小语言模型智能体提示注入防御

- **英文标题**：CapLite: Prompt-Injection Defense for Small Language Model Agents without Model-Written Security Artifacts
- **作者**：Zimo Xu、Wenzhuo Liu、Hideki Nakayama
- **分类**：cs.AI, cs.CL, cs.CR
- **发布时间**：2026-11-12 17:07:22 UTC
- **链接**：[原文摘要](https://arxiv.org/abs/2611.17115v1) · [PDF](https://arxiv.org/pdf/2611.17115v1)
- **匹配方向**：LLM + Agent

### 快速理解

- **研究背景**：现有提示注入执行式防御依赖智能体自身模型生成安全工件，再由外部代码强制执行；但小语言模型是否可靠地编写这些关键工件尚未被检验。
- **核心创新**：CapLite 不再让模型编写安全工件，而是直接从工具 schema 派生写入策略，并通过“先提交写、后读工具结果”的顺序切断注入文本影响写入的机会。
- **方法概览**：CapLite 在每个写调用前校验所有决定影响对象或目标的参数是否已在用户请求中明确出现；实验在 15 个开放权重模型和 13,935 个 AgentDojo 受攻击情节上评估，并与 CaMeL、Progent、IPIGuard、DRIFT 对比。
- **结果与结论**：SLM 自写的安全工件普遍脆弱：Progent、IPIGuard、DRIFT 分别在 14、13、11 个模型上被攻破，CaMeL 程序在最多 68% 情节中失败；CapLite 在所有 13,935 个受攻击情节中零攻击成功，攻击下效用为 29.0%（CaMeL 为 27.2%），每情节 17.1k token，仅为 CaMeL 的 18%，并取得最高每 token 效用。
- **一句话 takeaway**：小语言模型智能体不应被信任来编写关键安全工件；低成本、schema 派生且面向用户请求校验的写门控，可显著增强写入完整性并保持高效用与高效率。

**中文摘要**：针对提示注入的执行式防御（如 CaMeL、Progent、IPIGuard、DRIFT）通常要求智能体自身模型编写安全工件（程序、权限策略、依赖图或约束列表），再由代码强制执行。作者质疑小语言模型（SLM）智能体是否可信地编写这些工件。在 15 个开放权重模型（其中 13 个为 1.7B–12B 参数）上，这些模型并不可信：由智能体模型编写的策略、图和约束分别使 Progent、IPIGuard、DRIFT 在 14、13、11 个模型上被攻破，而 CaMeL 的程序在多至 68% 的情节中无法运行。为此提出 CapLite：其策略来自工具 schema，在读取任何工具结果之前提交写调用，并且仅当决定影响对象或目标的每个参数都在用户请求中明确陈述时才允许写入。这保证了写入完整性：注入文本不能新增写入，且任何写入不会到达用户未指定的接收者、金额、对象或目的地。在 13,935 个受攻击的 AgentDojo 情节中，没有攻击成功。CapLite 在攻击下的效用与 CaMeL 相当（29.0% 对 27.2%），并且每情节 token 少于所有其他执行式防御及无防御智能体：17.1k，占 CaMeL 的 18%，是所有执行式防御中每 token 效用最高者。

## 6. 通过程序进化发现有效的智能体记忆设计

- **英文标题**：Discovering Effective Agent Memory Designs through Program Evolution
- **作者**：Xinheng Ding、Seyyed Saeid Cheshmi、Ziyang Zhang、Tairan Chen、Wenya Xie、Yu Hou、Rui Zhang、Zirui Liu
- **分类**：cs.CL, cs.AI
- **发布时间**：2026-11-12 16:42:04 UTC
- **链接**：[原文摘要](https://arxiv.org/abs/2611.17068v1) · [PDF](https://arxiv.org/pdf/2611.17068v1)
- **匹配方向**：LLM + Agent

### 快速理解

- **研究背景**：智能体记忆系统的设计长期以来依赖人工经验，缺乏系统性探索有效性背后设计选择的工具。程序进化为自动发现和优化记忆设计提供了新的思路。
- **核心创新**：提出 MAPE 框架，能从最小种子程序出发，借助标准化生命周期接口与迭代式“诊断—提议”循环进化出完整的记忆程序，实现记忆设计的自动化发现。
- **方法概览**：采用程序进化方法：以最小种子为起点，通过标准化生命周期接口封装记忆系统，在迭代循环中不断诊断当前程序的不足并生成改进提议，从而在 LoCoMo 和 LongMemEval 等基准上搜索高性能、低成本的记忆设计。

- **一句话 takeaway**：两个关键设计模式得到验证：保留原始对话作为可检索证据可避免细节丢失，按查询意图组合检索证据能提升回答效果；此外，在搜索目标中纳入服务成本会促使计算从记忆构建转移到查询时的选择性处理，为智能体记忆设计提供可借鉴的实证经验。

**中文摘要**：程序进化为发现智能体记忆设计并研究其有效性背后的设计选择提供了一种有前景的途径。本文提出 MAPE 框架，通过标准化的生命周期接口和迭代式的“诊断—提议”循环，从最小种子程序出发进化出完整的记忆程序。在 LoCoMo 和 LongMemEval 基准上的实验表明，与人工设计的基线相比，绝对准确率提升最高达 12%，而服务成本仅为其 35%；进一步的评估支持该设计在不同服务骨干网络和基准之间迁移。实证分析与消融实验识别并验证了两个反复出现的设计模式：一是将原始对话保留为可检索的证据，可保留从提取记忆中遗漏的细节；二是根据查询意图对检索到的证据进行组合，有助于回答模型有效利用这些信息。将组合模块移植到五种现有记忆系统中，五种系统的准确率均得到提升。除这些模式之外，搜索目标还决定了计算资源的分配方式：在优化准确率的同时优化服务成本，会将计算从基于 LLM 的记忆构建转移到查询时的选择性处理上，同时保持有竞争力的准确率。这些发现为智能体记忆设计提供了实证经验。代码已开源。

## 7. 审计人工智能同行评审：基于真实科学论文的基准评测

- **英文标题**：Auditing AI peer reviewers: a benchmark on real scientific papers
- **作者**：Íñigo Zubeldia、Boris Bolliet、Francisco Villaescusa-Navarro、Pablo Villanueva-Domingo、Miles Cranmer
- **分类**：cs.CL, astro-ph.IM, cs.AI, cs.DL
- **发布时间**：2026-11-12 16:33:51 UTC
- **链接**：[原文摘要](https://arxiv.org/abs/2611.17052v1) · [PDF](https://arxiv.org/pdf/2611.17052v1)
- **匹配方向**：LLM + Agent

### 快速理解

- **研究背景**：LLM同行评审已被大规模使用，但现有评估难以衡量模型对不同类型科学错误的真实识别能力。本文面向真实科研论文建立审计基准，以检测率、分类型分严重度表现和误报率刻画评审系统。
- **核心创新**：该基准将一般性、数学、数值和引用四类错误按三级严重程度注入真实论文，并用干净论文评估误报。Skepthical通过引用检索、计算机代数验证和执行代码，将多工具核查整合进多智能体评审流程。
- **方法概览**：研究在天体物理学和机器学习两个领域各选取15篇近期 arXiv 论文，共注入357处错误，并评估12个评审系统。系统比较覆盖模型、提示、Claude Code脚手架和公开评审工具，同时发布注入错误、裁决日志与评测流程。
- **结果与结论**：模型选择是检测率差异的最大来源，相同提示下三个前沿LLM的总检测率相差约50个百分点。在天体物理学中，Claude Code提升数学和数值检测，Skepthical的引用错误检测显著领先；在机器学习中，这一引用优势消失，其表现与最佳单LLM统计上相近。多数系统误报率低于10%，数学标记是主要误报来源。
- **一句话 takeaway**：AI同行评审的性能不仅取决于提示，更取决于底层模型；工具应针对模型无法可靠完成的核查环节设计。引用检索对模型文献知识较弱的领域价值更大，而高检测率必须与误报控制一并评估。

**中文摘要**：基于大语言模型的人工智能同行评审已进入生产规模应用，但其评估仍然不足。本文提出一个面向真实科学论文的基准，通过向论文中注入四类可客观定位的错误（一般性问题、数学问题、数值问题和引用问题），并设置三个严重程度，测量各评审系统按错误类型和严重程度的检测率，以及在未修改干净论文上的误报率。作者还提出多智能体评审系统 Skepthical：通过检索被引用论文核验基于引用的主张，利用计算机代数系统核验数学内容，并通过执行代码核验数值主张。研究在两个语料库上进行了评测，分别为天体物理学和机器学习领域的15篇近期 arXiv 预印本，共注入357处错误，并评估了12个评审系统，包括六个单LLM评审器、两种Claude Code配置、三个公开评审系统和Skepthical。结果显示，模型选择对检测率影响最大：在相同提示下，三个前沿大语言模型在两个语料库上的总检测率相差约50个百分点。工具和脚手架只有在补足模型自身能力缺失时才有帮助：在天体物理学论文上，Claude Code相较单次Claude调用提升了数学和数值错误检测；强制引用检索使Skepthical在引用错误检测上大幅领先所有系统。然而，这一优势未在机器学习论文上显现，因为模型对机器学习文献更熟悉，Skepthical的引用检测率与最佳单LLM在统计上不可区分。多数系统的误报率低于10%，但误报率随提示、模型和脚手架而变化，其中数学错误标记是主要误报来源。作者同时发布了评测流程、注入错误和裁决日志，构成可复用的审计基准。

**中文摘要**：大语言模型智能体通过外部技能复用任务流程与工具使用经验。通用技能描述共享执行流程，但具体的工具选择、操作习惯和输出要求会因用户而异。在长程任务中，随着执行推进，子目标、可用输入和环境状态会不断变化，智能体需要从不断扩大的技能池中选择当前适用的技能，并为后续步骤准备候选技能。本文提出 Skill Adapter，实现通用技能的个性化修改与在线路由。系统从用户需求和执行反馈中提炼局部调整，将其作为 Adapter 与通用技能关联存储；路由智能体根据当前子任务、执行进度和环境反馈选择通用技能及适用 Adapter，并增量维护任务级在线技能库，供主 LLM 按需读取。系统还会预加载后续节点候选，并在实际输入确定后重新检查其适用性。强化学习分别利用修改收益和路由结果优化两类决策。我们在 ALFWorld、WebShop 和 SkillsBench 上评估 Skill Adapter；与 SkillRL 相比，平均任务成功率提升 11.43 个百分点，并在三个基准上都降低平均执行时间；当技能池扩展到 1000 个技能时，Skill Adapter 仍保持性能优势。
