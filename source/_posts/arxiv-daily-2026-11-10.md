## 2. 可验证智能体流量类别：一种面向智能体AI流量的受监管服务质量机制，并从仿真到真实内核对抗测试进行评估

- **英文标题**：Verifiable Agentic Traffic Class: A Policed Quality-of-Service Mechanism for Agentic AI Traffic, Evaluated from Simulation to Real-Kernel Adversarial Testing
- **作者**：Naveen Babu Narayanan Nair、Sajay Kurup
- **分类**：cs.LG, cs.AI, cs.NI
- **发布时间**：2026-11-10 15:33:22 UTC
- **链接**：[原文摘要](https://arxiv.org/abs/2611.14211v1) · [PDF](https://arxiv.org/pdf/2611.14211v1)
- **匹配方向**：LLM + Agent

### 快速理解

- **研究背景**：大型语言模型驱动的软件智能体产生不同于人类网页流量的流量模式，但现有路由器既没有专门的智能体流量类别，也无法核验发送方关于自身是智能体的声明。
- **核心创新**：VATC把可验证声明与强制降级结合起来：保留DSCP用于声明智能体流量，路由器侧分类器把与声明矛盾的流降级到尽力而为之后服务，并配合速率受限优先队列，在提供优先服务的同时抑制伪造型滥用。
- **方法概览**：作者在两种网络模拟器和真实Linux内核上，将VATC与静态DiffServ、信任标记的专用类别和fq_codel对照；测试覆盖稳定负载、构造突发、内核伪造洪泛、四特征在线分类器识别批量整形伪造者，以及真实智能体运行框架在拥塞链路上的排队占比。
- **结果与结论**：VATC在稳定负载下与DiffServ相当；突发仿真中智能体平均排队时延较DiffServ降低98%，人类时延增加12%；内核伪造洪泛下速率限制使人类时延低于DiffServ约11倍。无验证时DiffServ和严格配置fq_codel对合法智能体更有利；四特征分类器降级全部20个批量整形伪造者并使智能体时延达0.30 ms，但漏检6个复制智能体模式的伪造者，且在引入仿真时延后一个时序特征失效。真实运行框架中排队占总任务时间13%至63%，但流量为合成或沙盒规模。
- **一句话 takeaway**：VATC的关键价值在于把“声明优先”变成可验证、可降级的受监管QoS，而不是单纯信任DSCP标记；其主要边界也来自验证能力——复制智能体模式的伪造者和时延条件下的时序特征退化会削弱识别，因此结论更适合作为沙盒/合成规模下的机制证据而非现网定论。

**中文摘要**：建立在大型语言模型之上的软件智能体会产生不同于人类网页流量的流量，但路由器没有对应类别，也无法验证发送方自称智能体的说法。本文提出可验证智能体流量类别（VATC），它结合一个保留的差分服务代码点（DSCP）值来声明智能体流量、一个路由器侧分类器来把与声明相矛盾的流降级到在尽力而为流量之后服务的类别，以及一个速率受限的优先队列。研究在两个模拟器和真实Linux内核中，将VATC与静态差分服务（DiffServ）、信任标记的专用类别，以及每流公平排队调度器fq_codel进行了比较。稳定负载下，VATC与DiffServ表现相当。在构造的突发中，相对于DiffServ，VATC在仿真里把智能体平均排队时延降低了98%（假设判决即时），代价是人类时延增加12%；收益主要来自独立类别。在内核遭遇伪造洪泛时，速率限制使人类时延保持在DiffServ的1/11以下。没有验证机制时，DiffServ和配置严格的fq_codel给合法智能体的时延低于VATC；随后一个在线四特征分类器降级了全部20个批量整形伪造者，并给智能体带来0.30 ms时延，但漏掉了6个复制智能体模式的伪造者。在引入仿真网络时延后，分类器的一个时序特征不再能区分智能体流与人类流。在拥塞链路上的真实智能体运行框架中，路由器排队占总任务时间的13%到63%，具体取决于运行框架和所假设的模型时延。该流量为合成流量或沙盒规模。

## 3. Tree-Ising：通过比特级 Ising 编辑修复语言模型

- **英文标题**：Tree-Ising: Repairing Language Models with Bit-Level Ising Edits
- **作者**：Hadi Salloum、Ammar Ali
- **分类**：cs.LG
- **发布时间**：2026-11-10 15:32:04 UTC
- **链接**：[原文摘要](https://arxiv.org/abs/2611.14210v1) · [PDF](https://arxiv.org/pdf/2611.14210v1)
- **匹配方向**：LLM + Agent

### 快速理解

- **研究背景**：近期 MIT 的权重空间编程工作让前沿 LLM 智能体直接读写小模型权重以修复其推理循环，但该方法消耗近 9000 万 token、158 轮智能体交互和 50 次前向请求，成本高昂。本文要解决的问题是：能否用不依赖 LLM 智能体、代价极低的离散优化方式完成同样的修复。
- **核心创新**：本文将权重修复重新表述为模型自身 BF16 权重上的稀疏离散优化：在状态树表示中只允许保共享组指数和尾数的符号翻转与指数移位，并将目标精确分解为每个输出行一个的独立 QUBO（Ising）问题，用模拟退火或量子启发的模拟分岔在 GPU 上求解。
- **方法概览**：先用少量前向传播收集统计量，构造同时削弱循环方向、强化收敛方向并保持有产出 token 上输出不变的目标；再将其精确分解为逐行的 Ising/QUBO 子问题，在比特级状态树约束（仅符号翻转和指数移位、保留共享组尾数与指数）下用模拟退火或模拟分岔求解；层与剂量仅用基座模型选择。
- **结果与结论**：在 Qwen3.5-0.8B 的智能体修复层上，Tree-Ising 在 MATH-500 上达 54.6%，优于智能体编辑的 51.7%（基座为 7.9%），模拟分岔版本为 55.1%；五个数学基准全面超过智能体编辑，MATH-500 和 GSM8K 经多重比较校正后提升显著；同时少改 13%–17% 的权重、比特翻转减少 2.2–2.3 倍，仅需 4 次前向请求、零 LLM token、约 0.90 美元 GPU 成本；在 Qwen3.5-2B 上贪心 GSM8K 从 21.6% 升至 69.4%，并在 IBM Heron 上用 QAOA 演示了八变量子问题。
- **一句话 takeaway**：LLM 智能体昂贵的权重修复可以被精确分解为逐行的比特级 Ising/QUBO 问题，用经典退火或量子启发求解器以近乎零 token 成本取得更好且更稀疏的修复；QAOA 真机演示还表明该路线与量子计算硬件存在衔接可能。

**中文摘要**：权重空间编程是 MIT 近期由 Takehi 等人提出的工作，它使前沿大语言模型智能体能够读取网络的权重并写出修复方案。他们的 GPT-6 Astra 智能体在不使用梯度的情况下修复了 Qwen3.5-0.8B 的推理循环，共使用 158 次智能体轮次、8970 万 token 和 50 次前向传播请求。我们的方法 Tree-Ising 将这一修复问题转化为在模型自身 BF16 权重上的稀疏离散优化问题。前向统计定义了一个目标函数，用于削弱循环方向、强化收敛方向，并保持该层在有产出 token 上的输出不变。在状态树表示中（无损 BF16 存储作为特例），允许的编辑为符号翻转和指数移位，且保留所有共享组的指数和尾数。我们将该目标精确分解为独立的 QUBO（Ising）问题，每个输出行一个，并在 GPU 上用模拟退火或量子启发式模拟分岔求解。在智能体修复的两个层上，Tree-Ising 在 MATH-500 上达到 54.6%，在相同评估协议下优于智能体的编辑（51.7%），而基座模型的得分为报告中的 7.9%。模拟分岔求解器得到统计上无显著差异的修复结果 55.1%。两种求解器在全部五个数学基准上都优于智能体编辑，并在多重比较校正后于 MATH-500 和 GSM8K 上取得统计显著提升。我们的方法少修改 13% 至 17% 的权重，并将 BF16 比特翻转次数降低 2.2 至 2.3 倍。它仅需四次前向传播请求和零 LLM token，退火流程的 GPU 时间成本约为 0.90 美元。在 Qwen3.5-2B 上，仅用基座模型选择层和剂量时，同一流程将贪心 GSM8K 准确率从 21.6% 提升至 69.4%。作为概念验证，我们在 IBM Heron 处理器上用 QAOA 执行了一个八变量的修复子问题。

## 5. ProofCoder：面向自动化软件验证的连续推理

- **英文标题**：ProofCoder: Continuous Reasoning for Automated Software Verification
- **作者**：Martim Afonso、Inês Lynce、Maurizio Morisio、João F. Ferreira
- **分类**：cs.SE, cs.AI
- **发布时间**：2026-11-10 13:59:49 UTC
- **链接**：[原文摘要](https://arxiv.org/abs/2611.14106v1) · [PDF](https://arxiv.org/pdf/2611.14106v1)
- **匹配方向**：LLM + Agent

### 快速理解

- **研究背景**：形式化验证依赖证明助手保证软件正确性，但人工构造证明耗时且需要专业知识，现有基于大语言模型的自动化证明方法多将模型限制在由外围系统主导检索、状态管理与回溯的僵化策略生成循环中。
- **核心创新**：ProofCoder将定理证明重新定义为编码智能体问题，让模型在整个证明搜索中连续推理，自主决定何时收集信息、检查证明状态、修改已有片段或回溯，支持策略级与整证两种粒度。
- **方法概览**：作者在Rocq上实现ProofCoder：代理直接生成和修改证明代码，利用证明助手的编译反馈驱动信息获取、证明修复与回溯决策，在AutoRocq基准的280个高难度验证任务上评估并做了连续推理与生成粒度的消融实验。

- **一句话 takeaway**：有效的自动化软件验证不只是更优的策略选择，连续推理与反馈引导的证明修订是稳健证明合成的关键，这一范式有望推广到其他依赖形式化验证的场景。

## 20. RSI税：何时递归自我改进得不偿失

- **英文标题**：The RSI Tax: When Recursive Self-Improvement Is Not Worth the Cost
- **作者**：Yitong Zhang、Ang Li、Yisen Wang
- **分类**：cs.LG
- **发布时间**：2026-11-10 03:48:55 UTC

### 快速理解

- **研究背景**：递归自我改进（RSI）假设智能体可用自身任务经验持续提升能力，但其实际收益必须覆盖自我改进与任务执行的全部开销，而这一成本在以往评估中常被忽略。
- **核心创新**：提出"RSI税"概念，将自我改进过程（验证、探索、写入）产生的token成本纳入端到端评估，并在持续任务流上采用先评分后更新的协议衡量真实权衡。

- **一句话 takeaway**：高成本的RSI程序存在实际局限：智能体的改进收益未必抵得上改进过程的开销；未来应设计联合优化RSI税与任务执行成本、同时保证能力持续增长的RSI目标。

**中文摘要**：递归自我改进（RSI）旨在利用智能体自身的任务经验来提升其能力。其实际价值取决于性能收益能否证明自我改进与任务执行的全部成本是合理的。我们在持续任务流上评估这一权衡，在每个任务被评分之后、其反馈才被用于后续更新。我们将自我改进过程所产生的token成本定义为\emph{RSI税}，并将其与任务执行成本一并纳入端到端评估。在六种方法和两个语言模型上，一个有界笔记（bounded-note）基线在观测准确率上达到或超过了Meta-Harness、EvoSkill和RRSI，同时平均总token节省达65.6-71.0%。我们将RSI税分解为验证成本、探索成本和写入成本，并追踪相关状态或产物的后续使用情况。对于这三种RSI方法，验证成本占RSI税总量的74.8-93.6%。此外，相当一部分RSI税与后续在所评估任务流中并未被再次使用的状态或产物相关联。这些结果揭示了高成本RSI程序的一个实际局限：被部署智能体的性能改进未必能证明改进过程的开销是合理的。它们促使我们设计这样的RSI目标：在确保智能体能力沿任务流持续增长的同时，联合优化RSI税与预期任务执行成本。
