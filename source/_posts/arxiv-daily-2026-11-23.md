## 2. 面向工具调用型LLM智能体的意图条件化参数中介：拦截可信但未经授权的参数

- **英文标题**：Intent-Conditioned Argument Mediation for Tool-Using LLM Agents: Blocking Trusted-but-Unauthorized Arguments
- **作者**：Yulliwas Ameur、Miqeas Pedro Mendes、Samia Bouzefrane
- **分类**：cs.AI, cs.CR
- **发布时间**：2026-11-23 14:22:21 UTC
- **链接**：[原文摘要](https://arxiv.org/abs/2611.30745v1) · [PDF](https://arxiv.org/pdf/2611.30745v1)
- **匹配方向**：LLM + Agent

### 快速理解

- **研究背景**：LLM智能体把用户请求与检索内容转化为工具调用，调用可能误达错误的接收者、端点、文件或参与者。现有的参数级来源防护只能拦截来自不可信内容的参数值，却会放行“来源可信但用户从未请求”的参数，形成授权漏洞。
- **核心创新**：提出IntentFlow这一意图条件化的参数中介思路：在来源策略之外引入意图契约，专门封堵“可信但未授权”（trusted-but-unauthorized）参数这一来源防护无法覆盖的攻击面，且无需修改上游规划器。
- **方法概览**：IntentFlow作为中介层置于未经修改的规划器与工具之间，对每个承载权限的参数同时对照意图契约与来源策略进行校验；评估结合oracle意图/注入标签与声明角色，覆盖200次攻击的合成基准、50次可信但未授权攻击、AgentDojo离线重放及一个真实在线规划器。
- **结果与结论**：合成基准上攻击成功率由仅来源防护的50.5%降至12.0%［8.2–17.2%］，残余成功攻击均只改动内容或载荷字段；200个配对良性任务零误拦、50个难例误拦4个；50次可信但未授权攻击全部被拦截（仅来源方案全部放行，CaMeL式方案虽全拦但误拒16/50良性任务）；AgentDojo重放中拦截全部20次攻击且良性成功率75%；在线规划器的110次攻击中全部17个被篡改调用均被拦截。
- **一句话 takeaway**：仅靠来源追踪不足以约束工具调用的授权边界，将意图契约与来源策略联合校验能以较低误拦代价堵住“可信但未授权”漏洞，相比CaMeL式严格检查在安全性与可用性之间取得了更好的平衡。

**中文摘要**：LLM智能体将用户的请求和检索到的内容转化为工具调用，而一次调用可能指向错误的接收者、端点、文件或参与者。参数级来源（provenance）防护会在这些值来自不可信内容时将其拦截，但会接受一个可信却并非用户所请求的值。IntentFlow是位于未经修改的规划器（planner）与其工具之间的一个中介层，它依据意图契约（intent contract）和来源策略（provenance policy）检查每一个承载权限的参数。在一个包含200次攻击的合成基准上（采用oracle意图标签与注入标签、已声明的角色），攻击成功率从仅使用来源防护时的50.5%降至12.0%［8.2–17.2%］；每一个仍然成功的攻击都只篡改了内容或载荷字段。IntentFlow在200个配对良性任务中无一误拦，在50个高难度任务中误拦4个。在50次“可信但未授权”攻击上，仅来源中介执行了全部50次，而IntentFlow一次也未执行；CaMeL式检查同样拦截了全部50次，但拒绝了50个良性任务中的16个。在离线的AgentDojo衍生重放中，IntentFlow在75%良性任务成功率下拦截了全部20次攻击，CaMeL式检查亦如此；Progent式白名单拦截了19次并保留了全部良性任务。在使用一个真实在线规划器并采用相同oracle的实验中，该中介在110次攻击中拦截了规划器提出的全部17个被篡改调用。

## 3. LLM智能体的可迁移安全评估（Transport-Safe Evaluation）：轨迹依赖的评判误差与任意时刻有效（Anytime-Valid）的审计

- **英文标题**：Transport-Safe Evaluation of LLM Agents: Trajectory-Dependent Judge Error and Anytime-Valid Auditing
- **作者**：Yulliwas Ameur、Samia Bouzefrane、Soumya Banerjee
- **分类**：cs.AI, stat.ME
- **发布时间**：2026-11-23 14:19:52 UTC
- **链接**：[原文摘要](https://arxiv.org/abs/2611.30742v1) · [PDF](https://arxiv.org/pdf/2611.30742v1)
- **匹配方向**：LLM + Agent

### 快速理解

- **研究背景**：LLM智能体的排行榜通常依赖LLM评判器打分，并假定一次性测得的评判器错误率可复用于所有智能体；但当评判误差随轨迹变化、且各智能体的成败轨迹分布不同时，这种“迁移”校正会引入系统偏差。
- **核心创新**：论文推导了标量校正在轨迹依赖评判误差下的确切渐近偏差，并构建了从可识别性检验到同时秩推断的完整检查链，同时提出以随机审计支撑的AIPW校正和e-过程置信序列，实现自适应审计与任意停止下仍然有效的“随时有效”审计。
- **方法概览**：作者在四个智能体的半合成基准上对比神谕校准的标量校正法与采用均匀或设计感知随机审计的AIPW；另设48单元压力测试，将校准标签量从600变化到4800以考察有效目标支持度；在缺乏校准支持时报告有效界或敏感性集合，并用e-过程置信序列处理自适应审计与任意停止。
- **结果与结论**：标量校正即使有神谕校准也表现很差：最大偏差0.245、平均逐点覆盖率0.016、250次重复中0次恢复完整排名；带审计的AIPW最大偏差低于0.003、覆盖率0.939–0.950，压力测试中平均绝对误差稳定在0.018–0.020，而有效目标支持度仅从0.209升至0.805。
- **一句话 takeaway**：LLM评判器的错误率不能“测一次、处处用”：轨迹依赖的评判误差会使校正后的智能体成功率严重失真且排名不可信；引入小规模随机审计并结合AIPW与e-过程置信序列，能以很低的标注成本获得近乎无偏、覆盖率合格且支持任意停止的评估结论。

**中文摘要**：大语言模型（LLM）智能体通常由LLM评判器进行排名，而评判器的错误率往往只测量一次，随后被复用到每个智能体上。当评判器的误差依赖于轨迹、且不同智能体在成功或失败时产生的轨迹存在差异时，经过校正的成功率就可能产生偏差。我们推导了这种偏差的确切渐近形式，并给出了一条从可识别性到同时秩（simultaneous ranks）的完整检验链。在一个四智能体半合成基准上，采用神谕校准的标量校正法最大偏差达0.245，平均逐点覆盖率仅0.016，且从未恢复出完整排名（250次重复中0次成功）。而采用均匀审计或设计感知随机审计的增广逆概率加权（AIPW）方法，最大偏差保持在0.003以下，平均逐点覆盖率分别为0.939和0.950。在一项48单元的压力测试中，当校准标签从600个增加到4800个时，有效目标支持度仅从0.209升至0.805，而经审计的AIPW始终保持0.018–0.020的平均绝对误差。当缺乏校准支持，或评判器依赖性处于外部论证的界限之内时，我们报告有效的界或敏感性集合，并将其传递到秩集合中。对于稳定的目标，e-过程置信序列在可预测的自适应审计和任意停止规则下依然保持有效。

## 4. Oops!... I Parsed It Again：针对 LLM 智能体的工具调用走私（Tool-Call Smuggling）攻击

- **英文标题**：Oops!... I Parsed It Again: Tool-Call Smuggling Against LLM Agents
- **作者**：Igor Santos-Grueiro、Daniel Romero-Ruiz
- **分类**：cs.CR, cs.AI, cs.SE
- **发布时间**：2026-11-23 12:56:26 UTC
- **链接**：[原文摘要](https://arxiv.org/abs/2611.30624v1) · [PDF](https://arxiv.org/pdf/2611.30624v1)
- **匹配方向**：LLM + Agent

### 快速理解

- **研究背景**：LLM 智能体依赖工具调用执行任务，而同一调用的字节会在供应商、网关、SDK、框架、守卫和执行器等多个环节被反复解析。JSON 规范将重复键取舍等歧义留给各解析器自行处理，导致不同组件对同一段字节可能理解不一致。
- **核心创新**：论文首次提出并命名了"工具调用走私"（tool-call smuggling）攻击，系统归纳出六种使相同字节产生不同调用的解析分歧方式。同时构建了覆盖 17 个固定版本解析器与校验器配置的差分测试工具，并给出"单次解析、按批准 schema 裁剪、以调用 ID 加封传输"的端到端防御方案。
- **方法概览**：作者将完全相同的字节输入 17 个固定版本的解析器与校验器配置进行差分测试，量化各组件间的解析分歧（包括两个官方 MCP SDK）。随后在 τ-bench 和 AgentDojo 的任务上验证攻击：在传输途中改写调用字节，并利用模型读取的内容诱使十个受测模型把重复键逐字复制进参数中的 JSON 文本，使 Python 守卫与 Go 执行器产生不同解读。
- **结果与结论**：大多数解析器对在某些输入上不一致，甚至两个官方 MCP SDK 也接受不同输入；能改写传输字节的攻击者成功取消了其他客户的预订、创建了守卫按名禁止的文件，而审计日志只记录被批准的调用；恶意服务器还可通过复制合法工具 schema 并添加一个字段，诱使模型在守卫不可见的情况下填入用户数据。所提出的防御方案阻断了全部 7,412 个构造输入及所有构建的攻击。
- **一句话 takeaway**：工具调用的安全性取决于整条链路上解析的一致性，而不仅仅是守卫的判定逻辑。对每个调用只解析一次、仅保留批准 schema 的字段并以调用 ID 加封传输，能从根源上消除此类走私攻击，对设计 LLM 智能体安全管线具有直接的工程指导意义。

**中文摘要**：LLM 智能体通过工具调用来执行动作：模型以 JSON 形式写出调用的参数，守卫（guard）决定该调用能否运行，执行器（executor）负责运行它。同一段字节会被解析多次——由模型供应商、网关、SDK、框架、守卫和执行器分别解析。JSON 把一些选择留给了各个解析器，例如重复的键以哪一份为准。当守卫与执行器做出不同选择时，守卫批准的是一个调用，执行器运行的却是另一个，而审计日志记录的只是被批准的那个。我们提出了这种攻击——工具调用走私（tool-call smuggling），并在整个技术栈上对其进行了研究。我们描述了六种使相同字节产生不同调用的方式，并构建了一个差分测试工具，将完全相同的字节输入到 17 个固定版本的解析器与校验器配置中；大多数解析器对在某些输入上存在分歧，甚至两个官方 MCP SDK 也会接受不同的输入。在来自 τ-bench 和 AgentDojo 的任务上，一个能够在传输途中改写字节的攻击者取消了另一位客户的预订、创建了一个守卫按名字禁止的文件，而审计日志只记录了被批准的那个调用。模型所读取的内容只能在字符串内部造成守卫与执行器的分裂：在我们观察到的情况中，所测试的十个模型都不会在调用本身中写入重复键或伪装键，但会把这类键逐字复制到参数中的 JSON 文本里，而 Python 守卫和 Go 执行器对这段文本的解读并不相同。一个恶意服务器复制合法工具的公开 schema 并添加一个字段（并附说明文字加以解释），就能诱使模型用用户数据填写该字段，而这一切守卫无法看到。对每个调用只解析一次（包括其中的 JSON 文本），只保留已批准 schema 中的字段，将其交给执行器并在传输途中以调用 ID 加封，这一方案阻断了全部 7,412 个构造输入以及我们构建的每一种攻击。

## 5. SuSi-RAG：面向设备维护的混合图RAG方法

- **英文标题**：SuSi-RAG: A Hybrid Graph RAG for Equipment Maintenance
- **作者**：Hansi Zhang+、Wilma Johanna Schmidt+、Wanlin Yang、Xiaozhi Shen、Adrian Paschke、Evgeny Kharlamov
- **分类**：cs.IR, cs.AI, cs.DB
- **发布时间**：2026-11-23 12:27:46 UTC

### 快速理解

- **研究背景**：制造业中的设备维护高度依赖专家知识，但相关文档分散在异构的格式与来源中，检索与利用困难。传统基于向量的RAG难以处理真实维护查询中常见的复杂因果链和跨领域知识综合两类问题。
- **核心创新**：提出SuSi-RAG这一混合Graph RAG方案，用子图相似度来匹配用户查询与维护记录，而非仅依赖向量相似度。同时给出了在真实产线上长期运行的工业级部署案例及集成的运行反馈更新回路。
- **方法概览**：将维护记录组织为图结构，通过计算用户查询与维护记录之间的子图相似度来检索相关知识并生成答案，以应对因果链和跨领域查询；系统还包含一个集成的运行反馈回路，用于根据使用反馈持续更新SuSi-RAG。
- **结果与结论**：SuSi-RAG在博世一条在用生产线上运行超过八个月，处理了10,664次问答交互，答案准确率上限达96.25%（确认错误率3.75%）；概念验证中，相比基于向量的基线，top-1检索准确率从61.5%提升至96.2%，专家评定答案质量从44.9%提升至84.1%。

**中文摘要**：在制造业领域，设备维护任务依赖于专家知识，而这些知识文档往往以异构的格式和来源存储。利用检索增强生成（RAG）来增强大语言模型（LLM），对于打通这些分散的知识很有前景，但传统的基于向量的RAG在面对真实维护查询中普遍存在的两个特征时表现出弱点：复杂的因果链和跨领域综合。为解决这一问题，我们提出了SuSi-RAG，一种混合Graph RAG方案，通过子图相似度将用户查询与每条维护记录进行匹配。本工作展示了一个实际在用的系统：SuSi-RAG已在博世（Bosch）一条正在运行的生产线上运行超过八个月，处理了10,664次问答交互，并展现出96.25%的答案准确率上限（确认错误率为3.75%）。在一项概念验证中，与基于向量的基线相比，SuSi-RAG将top-1检索准确率从61.5%提升至96.2%，专家评定的答案质量从44.9%提升至84.1%。我们还提出了一个集成的运行反馈回路，用于持续更新SuSi-RAG。

## 6. HWRE-Bench：LLM 智能体能否理解并非由它们自己设计的硬件？

- **英文标题**：HWRE-Bench: Can LLM Agents Understand Hardware They Did Not Design?
- **作者**：Peilong Zhou、Cangyuan Li、Kaiyan Chang、Ying Wang
- **分类**：cs.AI
- **发布时间**：2026-11-23 10:18:07 UTC
- **链接**：[原文摘要](https://arxiv.org/abs/2611.30422v1) · [PDF](https://arxiv.org/pdf/2611.30422v1)
- **匹配方向**：LLM + Agent

### 快速理解

- **研究背景**：现有针对 LLM 智能体的硬件基准都沿正向设计流程评测（从规格到 RTL、版图或修复缺陷），尚无基准考察智能体能否反向理解由他人完成的已实现硬件产物，而正向流程每一步都会丢失名称、层次、字级结构等关键信息。
- **核心创新**：HWRE-Bench 是首个面向智能体硬件逆向工程的基准，其核心设计是要求用产物本身无法提供的可执行交付物来证明理解，并为每项任务设置必须零分的“复制网表”强制对照，以防周期精确的网表直接泄题；基准覆盖五个赛道、四个信息损失等级和白盒/黑盒访问模式。
- **方法概览**：作者在四个原创种子任务、16 种条件下对两个 LLM 智能体进行了 148 次试点运行，并记录阶段标注的轨迹，比较智能体在版图与网表、有无保持等价性混淆等条件下的表现。
- **结果与结论**：智能体自行构建了版图提取器，对脱敏版图的审计可靠性与网表相当但轮次约多 27%；无密钥等价性混淆不改变通过率和缺陷修复得分；智能体是否读取结构取决于任务表述而非必要性；提供商安全过滤器拦截了某智能体在审计任务上 16% 的运行。
- **一句话 takeaway**：仅凭通过率无法证明智能体真正理解了硬件结构，评测应要求超越等价性验证的可执行交付物，并显式报告运行有效性（如被安全过滤拦截的情况）。

**中文摘要**：现有的 LLM 智能体硬件基准都沿着正向设计流程运行，即从规格说明出发得到 RTL、版图或缺陷修复。我们提出一个反向问题：给定一个已实现的产物，例如版图、门级网表或受保护的仿真模型，智能体能否弄清它的功能，并利用这些知识采取行动？我们基于一个观察提出了 HWRE-Bench——一个面向智能体硬件逆向工程的基准。正向流程的每一步都会丢弃信息（名称、层次结构、字级结构、生成器参数、编程模型），而逆向工程任务要求智能体恢复丢失的信息，并用一个仅凭该产物本身无法提供的可执行交付物来证明这一点。由于版图提取如今已是机械性操作，且正确的网表本身已是周期精确的模型，每项任务都带有一个强制性的“复制网表”对照，该对照必须得零分。HWRE-Bench 涵盖五个赛道（Extract、Abstract、Audit、Interoperate、Modify）、四个信息损失等级以及白盒与黑盒两种访问方式，全部基于原创设计。我们报告了一项试点实验：两个智能体在四个种子任务、16 种条件下共 148 次运行，并带有阶段标注的轨迹。智能体自行构建了版图提取器，对脱敏版图的审计可靠性与对网表的审计相当，但所用轮次约多 27%。无密钥的、保持等价性的混淆既不改变通过率，也不改变缺陷修复得分。智能体是否真正读取了结构取决于任务表述方式而非必要性，因此仅凭通过率并不能表明理解。提供商的安全过滤器拦截了某个智能体在审计任务上 16% 的运行。这些结果主张采用超越等价性验证的交付物，并明确报告运行的有效性。

## 7. AI评审者中的披露偏差（Disclosure Bias in AI Reviewers）

- **英文标题**：Disclosure Bias in AI Reviewers
- **作者**：Jens Leysen、Noah Daniëls、Marco Favier、Bart Goethals
- **分类**：cs.CL, cs.AI, cs.DL
- **发布时间**：2026-11-23 10:12:01 UTC
- **链接**：[原文摘要](https://arxiv.org/abs/2611.30410v1) · [PDF](https://arxiv.org/pdf/2611.30410v1)
- **匹配方向**：LLM + Agent

### 快速理解

- **研究背景**：随着AI模型日益参与论文评审，许多会议和期刊要求作者披露AI使用情况，但这类声明本身是否会反过来影响AI评审者的判断尚不清楚。
- **核心创新**：该论文首次系统检验AI使用声明对AI评审者评分的因果影响，设计了从'未使用AI'到'AI作者'的九种声明版本，并区分了'AI全权完成'与'AI辅助'两类披露的不同效应。
- **方法概览**：作者仅改动150篇ICLR 2027投稿的AI使用声明（最多九个改编自真实声明的版本），由六个AI评审者（决策模型Jev及五个大语言模型）进行评分，共收集23,652份评审并做显著性比较。
- **结果与结论**：当声明称AI完成全部工作时，所有评审者的平均评分均显著低于'未使用AI'声明；'AI研究智能体'声明显著拉低Jev、Sonnet和Argon的评分；而对写作、编码和研究辅助类披露，没有任何评审者的评分与无AI声明存在显著差异。
- **一句话 takeaway**：披露'AI全权完成'会触发AI评审者的惩罚效应，而常规AI辅助披露则不会；这一惩罚能否改变论文接收结果，取决于评审者在接收边界附近的区分精细度与一致性、惩罚的分布方式以及披露AI使用的论文普遍程度。

**中文摘要**：AI模型正越来越多地参与论文评审，许多会议和期刊现在要求作者说明其如何使用AI。这种AI使用声明是否会改变AI评审者对论文的评分，进而改变哪些论文被接收？在一项初步研究中，我们仅改动了150篇ICLR 2027投稿的AI使用声明，最多设置九个版本，这些版本改编自真实声明：从没有使用AI，到写作辅助和代码编写，再到AI研究智能体和AI作者。六个AI评审者对这些版本进行了评分：决策模型Jev，以及语言模型Claude Haiku 5.5、Claude Sonnet 5.5、Gemini 3.8 Flash、Gemini 3.1 Pro和Gemini 4 Argon。在共计23,652份评审中，我们发现：当声明称AI完成了全部工作时，每个评审者给出的平均评分都低于声明未使用AI的情形。'AI研究智能体'声明会显著降低Jev、Sonnet和Argon的评分。我们没有发现针对AI辅助的披露偏差证据：对于写作辅助、代码编写和研究辅助，没有任何评审者的评分与声明未使用AI时的评分存在显著差异。观察到的评分惩罚是否会改变论文的接收结果，取决于惩罚大小之外的更多因素：评审者在接收边界附近区分论文的精细程度与一致性、惩罚是分散在所有论文上还是集中在少数论文上，以及可能还有披露使用AI的其他论文数量。

## 8. 面向编程智能体的聚合反馈乐观在线学习（Optimistic Online Learning for Coding Agents with Aggregate Feedback）

- **英文标题**：Optimistic Online Learning for Coding Agents with Aggregate Feedback
- **作者**：Hao Luan、Hao Qiu、Zhi Zheng、See-Kiong Ng、Zhiyong Huang
- **分类**：cs.LG
- **发布时间**：2026-11-23 10:05:39 UTC
- **链接**：[原文摘要](https://arxiv.org/abs/2611.30405v1) · [PDF](https://arxiv.org/pdf/2611.30405v1)
- **匹配方向**：LLM + Agent

### 快速理解

- **研究背景**：LLM 编程智能体在执行与仓库、issue 追踪器和 CI 服务交互的长时程软件工程任务时存在行为漂移问题；激活引导虽可通过干预残差流规范行为，但现有方法对所有任务采用静态引导策略，且任务级可验证反馈只在任务完成时才出现，使单轮引导贡献不可观测。
- **核心创新**：将在线引导策略选择形式化为带延迟任务级反馈和残差流激活导出轮次级预测提示的多臂老虎机问题，并提出 Online Optimistic Activation Steering 元框架：用提示指导任务内策略选择，用终端任务级反馈校正累积奖励估计；理论上给出随提示精度提高而收紧的后悔界及关于预测误差与候选策略数的匹配下界。
- **方法概览**：在每个执行轮次根据残差流激活提取的预测提示乐观地选择候选激活引导策略，任务结束后用揭示的任务级奖励校正累积奖励估计，从而在延迟聚合反馈下实现在线策略自适应。
- **结果与结论**：理论方面证明了相对于事后最优固定策略的后悔上界随提示准确性提升而收紧，并给出与预测误差和候选策略数量相关的匹配下界；实验方面，在真实编程基准上该框架优于静态引导策略和朴素的在线自适应基线（摘要未给出具体数值）。
- **一句话 takeaway**：在长时程编程智能体中，用激活流提示驱动的乐观在线策略选择在仅有延迟聚合反馈时也能有效抑制行为漂移；提示越准确，选择引导策略的代价越低。

**中文摘要**：运行在 Web 开发平台上的大语言模型（LLM）编程智能体可以与代码仓库、问题追踪系统和持续集成服务交互，以执行长时程的软件工程任务。然而，行为漂移（behavioral drift）仍是此类多轮推理与行动轨迹中的主要瓶颈。为缓解这一问题，激活引导（activation steering）已成为一种通过干预 LLM 的 Transformer 残差流来规范智能体行为的有前景的方法。然而，现有方法通常在所有任务上应用静态的引导策略，忽视了单一策略很难在异构任务和不同执行轮次中都有效这一事实。这一局限促使我们在候选引导策略之间进行动态在线选择。但在长时程智能体场景中这样做颇具挑战：可验证的任务级反馈只有在任务完成后才会揭示，导致单个引导轮次的贡献无法被观测。为应对这一挑战，我们将在线引导策略选择形式化为一个带有延迟任务级反馈的多臂老虎机问题，并利用从残差流激活中导出的轮次级预测提示（hints）。在此形式化框架内，我们提出 Online Optimistic Activation Steering（在线乐观激活引导），这是一个元框架，利用提示来指导任务内的引导策略选择，并利用终端任务级反馈来校正累积奖励估计。在理论上，相对于事后最优固定策略，我们证明了随提示准确性提高而收紧的后悔界（regret bounds），并建立了关于预测误差和候选策略数量的匹配下界。在真实编程基准上的实证评估表明，我们的框架优于静态引导策略和朴素的在线自适应基线。

## 9. mini-psych-agent：通过交互式心理环境评估大语言模型智能体的人类相似行为

- **英文标题**：mini-psych-agent: Evaluating Human-Like Behavior in LLM Agents through Interactive Psychological Environments
- **作者**：Yi-Fei Cao、Tianxin Huang、Hanbo Xie、Jian-Qiao Zhu
- **分类**：cs.AI
- **发布时间**：2026-11-23 09:34:35 UTC
- **链接**：[原文摘要](https://arxiv.org/abs/2611.30365v1) · [PDF](https://arxiv.org/pdf/2611.30365v1)
- **匹配方向**：LLM + Agent

### 快速理解

- **研究背景**：LLM的行为由模型本身、智能体框架和测试时计算预算共同决定，同一模型在不同配置下表现差异巨大，这与心理学中同一人在不同激励和审慎程度下表现不同的现象类似。但现有将心理学任务用于LLM评估的工作多把任务转成静态文本提示，无法反映智能体行动改变环境与观察的动态性，而动态环境评估又很少检验行为是否像人。

- **方法概览**：作者构建了多个交互式心理环境，让配备不同智能体配置（如记忆模块、不同测试时计算预算）的LLM在其中交互完成任务，收集其行为轨迹，再用学习得到的人类策略模型衡量这些轨迹与人类行为的兼容程度。
- **结果与结论**：研究发现行为与人类的兼容性随LLM的智能体配置和具体心理任务而变化；加入记忆模块主要通过提高选择的可预测性（而非更接近人类）来提升兼容性。摘要未报告其他具体数值结果。
- **一句话 takeaway**：评估LLM智能体时不能只看骨干模型能力，还需同时考虑智能体支架（框架、记忆、计算预算）以及任务类型；记忆带来的可预测性提升不等于类人性提升，提示需要更全面的心理学启发式评估范式。

**中文摘要**：大语言模型（LLM）、其外部框架（harness）以及测试时计算预算共同决定了模型的行为。因此，同一个底层模型在被嵌入不同的智能体工作流或被分配不同量的测试时计算时，可能表现出显著不同的性能。心理学家在评估人类表现时面临类似的挑战：同一个人在不同激励和不同审慎思考水平下可能表现出不同的行为。因此，心理学任务为研究这类行为变异提供了一个理想的试验场。然而，当这些任务被改造用于LLM时，通常只是被转写为文本，以静态提示的形式重放固定的、以语言呈现的实验。这种形式并不适合智能体评估，因为在智能体评估中，行动会改变未来的观察和任务状态。另一方面，虽然动态环境在LLM智能体评估中十分普遍，但它们很少追问所得到的行为是否具有人类相似性。在此，我们弥合了这一差距：我们将心理学任务转化为智能体可以与之交互的动态环境，并使用一个学习得到的人类策略模型来评估所得到的行为轨迹与人类行为的兼容程度。在这些环境上，我们发现这种兼容性随LLM的智能体配置和心理任务的不同而变化，并且记忆主要通过使选择更具可预测性而非更具人类相似性来提升兼容性。这些发现促使我们在受心理学启发的环境中对LLM智能体进行更全面的评估，同时兼顾骨干模型及其智能体支架。

- **分类**：cs.CR, cs.AI, cs.LG
- **发布时间**：2026-11-23 08:24:44 UTC

- **匹配方向**：LLM + Agent

### 快速理解

- **研究背景**：现有 LLM 智能体安全基准（如 Agent Security Bench）以攻击成功率（ASR）作为比较智能体、攻击和防御的依据，隐含假设每个判定结果完全由被测系统决定。但作者发现，哈希种子、工具/证据排列顺序、失败运行的计分方式等不携带被测系统信息的“无内容状态”也会左右判定，且这些状态可被评估者或请求方操控，从而威胁评估结论的有效性。
- **核心创新**：论文提出了判定无干扰性（decision noninterference）这一要求，将无内容状态视为不可信输入，并构建了 TARE 框架：只有当报告效应超过无内容状态实测影响时才允许归因于智能体、攻击或防御，从而把“可复现”与“可归因”明确区分开。
- **方法概览**：作者在 ASB 上系统操纵无内容状态：改变 Python 哈希种子观察判定翻转，交换工具列表排序方向检验攻击者工具位置的影响，对同一证据重新排序测试七个 LLM 评判器的稳定性；随后用 TARE 的最坏情况测试和预先固定的测试，对十八种智能体—防御组合的防御效应进行归因分析。
- **结果与结论**：固定哈希种子下七个智能体运行结果完全一致，但改种子可翻转多达 17% 的判定（ASR 仅动 5 点）；工具正序排列使 ASR 最多上升 19 点；六个 LLM 评判器在证据重排后于 17%–91% 的动作上改变决定；TARE 仅将效应归因于三个防御中的两个（其一在两个智能体上方向相反），第三个经预先固定的测试确认带来 4.8 点下降，且被归因的下降中 35%–69% 的“被阻止攻击”其实未发生任何工具调用却被 ASB 计为攻击失败。
- **一句话 takeaway**：可复现的评估结果并不等于可归因的结果：安全基准中的排序、种子等无内容状态足以系统性改变判定和 ASR，甚至让防御效果被高估或方向颠倒。评估 LLM 智能体安全性时应显式报告无内容状态的影响，否则基于 ASR 的比较结论不可靠。

**中文摘要**：LLM 智能体的安全基准通常记录每次攻击是否成功，并通过攻击成功率（ASR）来比较不同智能体、攻击和防御。此类比较仅在智能体、攻击和防御确实导致每个判定结果时才有效。我们表明，判定结果还依赖于无内容状态：即运行中不携带任何关于被测系统信息的细节，例如 Python 哈希种子、工具或证据的顺序，以及失败运行的计分方式。我们要求这种状态不影响任何判定（判定无干扰性），并将其视为不可信输入，因为评估者和基于 LLM 的门控系统的请求方都可以选择这种状态。我们的框架 TARE（Testing Attribution of Reported Effects，报告效应归因测试）仅当某个报告效应超过无内容状态所测得的影响时，才将其归因于智能体、攻击或防御。在 Agent Security Bench（ASB）上，使用固定哈希种子时，来自四个模型家族的七个智能体的运行结果完全一致，但改变种子会改变单个智能体多达 17% 的判定结果，而 ASR 最多仅变动 5 个百分点。种子通过工具顺序起作用：将工具列表正序排序而非逆序排序会使 ASR 最多上升 19 个百分点，因为 ASB 的命名约定会把攻击者工具排在前面。当对相同证据重新排序时，七个 LLM 评判器中有六个会在 98 个待判定动作中的 17%–91% 上改变其决定。在十八种智能体—防御组合中，TARE 的最坏情况测试仅将效应归因于三个防御中的两个，其中一个在两个智能体上呈现相反方向；一个预先固定的测试确认了第三个防御带来了 4.8 个百分点的下降。在被归因的下降中，35%–69% 被阻止的攻击是在未发起任何工具调用的情况下结束的，而 ASB 将其计为攻击失败。因此，可复现的判定并不必然是可归因的，对 LLM 智能体的安全评估应报告无内容状态的影响。我们开源发布了 TARE、ASB 补丁以及全部判定结果表。

- **一句话 takeaway**：三平面表示被证明是一种上下文高效的MLLM三维体观察方式，使低成本MLLM智能体也能完成高质量的三维医学图像交互式分割标注。

**中文摘要**：交互式分割模型能够将少量点击转化为跨领域的分割预测，因此标注员只需判断预测中哪些位置仍需修正。标注由此变成一个“检查预测—再次点击”的循环，而该循环中的每一步都是一次视觉判断，这恰好适合通用的多模态大语言模型（MLLM）智能体。在本工作中，我们专注于让这些智能体在三维体数据上运行这一循环。然而，这类智能体中的MLLM只接受二维图像作为输入，因此智能体必须以二维方式观察三维体数据。由于循环会多次调用MLLM，这种观察方式必须在token上足够紧凑，以使每次调用都保持低成本，同时又要有足够的信息量来显示三维预测中的错误区域。我们用三平面（tri-planes）同时满足这两项需求，即三维体数据中交于同一点的三个正交平面。我们从理论上和实证上表明，三平面既具备上下文高效性，又保留了足够细节以显示三维预测中的错误区域。基于三平面，我们提出了TriSegAgent，一个迭代细化三维预测的MLLM智能体。在该智能体内部，MLLM仅在三平面上对预测进行判断，而一个视觉执行框架（visual harness）将每次判断在代码中转化为三维动作。为使循环可靠，该框架将每次点击精确放置在体数据中的一个体素上，并检查是否应接受三维预测。为评估该智能体，我们构建了一个多样化基准，包含来自35个公开医学数据集、涵盖三种成像模态的690个感兴趣区域（ROI）。使用前沿MLLM时，TriSegAgent的总体Dice比最强基线高出约10个百分点，且在小于3 cm的目标上优势更大。使用flash级别的MLLM时，其表现超过了一个近期基于前沿MLLM构建的三维分割智能体。

### 快速理解

- **研究背景**：用强化学习训练编程智能体时，软件任务的奖励由隐藏测试判定，但 SWE-Gym 等任务集合的测试只对照参考修复验证过，任务本身的奖励标注可能出错。错误的奖励标注会让模型学到错误的信号，因此数据质量尤其是奖励正确性成为关键问题。

**中文摘要**：强化微调（RFT）已成为推动大型推理模型（LRM）发展的核心范式，OpenAI的o3和R1系列等系统即为例证。尽管在LLM上取得了显著进展，但如何利用RFT将视觉感知、逐步推理和智能体式工具使用统一到一套连贯的训练范式中，仍是一个开放性挑战。本文提出视觉强化微调++（Visual-RFT++），这是一个统一框架，将RFT扩展到视觉感知任务和多模态智能体工作流，使LVLM能够基于图像进行推理、对图像执行操作，并通过可验证奖励评估自身输出。借助Visual-RFT++，开源LVLM不仅在多种视觉感知任务上取得显著提升，还获得了智能体能力，如搜索网络获取实时信息以及基于代码的图像操作（如裁剪、旋转和分析）。在细粒度分类、少样本检测、推理定位和开放词汇检测等视觉感知任务上，Visual-RFT++相比SFT带来显著提升，其中单次（one-shot）细粒度分类提升24.3个百分点，COCO 4-shot设置下提升21.0个百分点，LVIS上仅用几百个样本提升15.4个百分点。为评估智能体行为，我们提出了多模态智能体工具基准（MAT），包含MAT-Search和MAT-Coding。Visual-RFT++在MAT-Coding上相比基线提升18.6个F1/13.0个EM百分点，在MAT-Search上提升10.3个F1/8.7个EM百分点。它在2Wiki和HotpotQA等多跳问答基准上也取得29.3个F1和25.9个EM个百分点的提升，展现出强大的跨模态泛化能力。Visual-RFT++提出了一种数据高效、奖励驱动的框架，同时增强了视觉推理能力和智能体适应性。

- **英文标题**：Retrieval-Augmented Generation in the Agentic Era: Tradition, Present, and Prospect
- **作者**：Chenming Tang、Haolin Li、Yiran Li、Zixian Yang、Lizhu Zhai、Rui Sun、Qizhou Huang、Yunfang Wu
- **分类**：cs.CL
- **发布时间**：2026-11-23 07:25:50 UTC
- **链接**：[原文摘要](https://arxiv.org/abs/2611.30181v1) · [PDF](https://arxiv.org/pdf/2611.30181v1)
- **匹配方向**：LLM + Agent

### 快速理解

- **研究背景**：RAG 通过将冻结的语言模型与外部可更新知识库耦合，使生成有检索证据作为依据，从而缓解仅依赖参数化记忆的局限。随着智能体式工作流兴起，已有综述未充分覆盖其后出现的新工作，也缺乏对索引与编排环节的统一审视。
- **核心创新**：本文以一条贯穿离线索引、检索前、检索、检索后与编排的统一生命周期轴线来组织 RAG 全景，并首次将索引和编排提升为一等公民组件、将智能体式工作流视为独立范式加以系统梳理。
- **方法概览**：作为一篇综述，作者沿生命周期五阶段（离线索引、检索前、检索、检索后、跨阶段编排）对 RAG 方法进行分类整理，并额外归纳评估方法、应用场景与开放问题，重点补充既有综述之后出现的智能体相关工作。
- **结果与结论**：本文为综述性工作，摘要中未报告新的实验结果或数值；其主要产出是对智能体时代 RAG 的系统性分类框架，以及对评估、应用和未来开放问题的整理。
- **一句话 takeaway**：理解智能体时代的 RAG 需要把索引与编排当作核心组件，并以全生命周期视角审视各阶段；智能体式工作流已成为区别于传统 RAG 的独立范式，值得后续研究重点关注其评估与开放问题。

**中文摘要**：检索增强生成（RAG）将冻结的语言模型与外部可更新的知识相结合，使生成过程建立在检索到的证据之上，而非仅依赖参数化记忆。本工作通过在一条统一的生命周期轴线上对 RAG 进行梳理来描绘智能体时代的 RAG 图景，该轴线涵盖离线索引、检索前、检索、检索后以及对上述各阶段的编排。本文将索引与编排视为一等公民组件，将智能体式工作流视为一种独立的范式，并覆盖了既有综述之后出现的智能体相关工作。除这些组件之外，本文还涵盖了评估、应用以及面向未来探索仍待解决的开放问题。从传统到现状乃至未来，本工作从智能体时代的视角对 RAG 进行了系统性综述。
